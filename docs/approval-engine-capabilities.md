# 审批引擎能配出什么

这篇只回答一件事：界面上能配出什么样的流程，配完之后引擎实际怎么走。概念和运行时序在 [approval-module.md](./approval-module.md)。

采购单创建后进入待提审，金额超过一万走「部门负责人 → 财务」两级会签，不超过一万自动通过；财务那一步只能看金额、能改备注；通过后把单据状态改成「已生效」，并给 ERP 发一个 Webhook。下面每一节是这句话里的一个零件。用词跟流程设计页一致。

能挂审批的实体：线索、客户、商机、报价、合同、发票、订单、采购单，以及自定义表单。

## 什么时候拦

执行时机三个勾：创建、编辑、删除，可多选。三个时机各画一套图。

创建命中后，单据先变成待提审，不会自动提审。编辑命中后，业务事务提交完才提审，并且另开一个事务，避免条件读到提交前的旧数据。从没通过过的单据，编辑也按创建处理，只改成待提审。

删除命中后，删除本身不执行，等事务提交再提审。通过之后才真删；如果删除图的第一个节点就是结束，提审当下就删。已经有一条审批中的实例时，再提审直接返回，不重复发待办。

## 谁来审

审批人六种来源：指定成员、角色、指定上级、连续多级上级、指定部门负责人、连续多级部门负责人。

上级和部门负责人再选层级，第一级到第十级，方向是「从下至上」或「从上至下」。指定上级、指定部门负责人选的是指定层级；连续多级的两个选的是指定终点。层级存的是 `"1"`～`"10"`，不是用户 ID。链不够长就解析成空，交给审批人为空。

一个节点上多个人时，三人审批方式三选一：

- 会签：所有人都同意才过
- 或签：任何一人同意就过
- 依次审批：按顺序一个一个审。待办只发到当前这个人，他同意（或被自动跳过）之后才发下一个人

节点也可以不设人：自动通过，或者自动拒绝。自动拒绝是整单驳回，编辑时机还会回滚提审前快照，再跑驳回后操作。图的第一个节点就是自动拒绝时，提审当下就驳回，不进审批中。

## 走哪条路

条件组按连线顺序判断。一组里是若干条件分支，最后自动带「其它情况」：如触发条件均未满足，则进入此分支。多条条件之间用且、或连接。

算子是高级筛选那套：大于、大于等于、小于、小于等于、等于、不等于、区间、包含、不包含、属于、不属于、为空、不为空。字段名对的是详情接口返回对象里的属性名。子表写成 `子表字段.子字段`，任一行命中就算成立。比较抛错、算子认不出，这条条件当不成立。

**新值不等于旧值**不比较两个值，只问这个字段在不在提审时算好的变更列表里。创建没有变更列表，它永远不成立。它用来做「只有改了金额才走财务」；`金额 > 1000` 做不到，因为备注一改、金额本来就是 5000，条件照样成立。

## 审完之后

每个审批节点挂两组：通过后操作、驳回后操作。每组两样。

字段更新：把字段改成固定值，每行一个启用开关。引擎只把「字段 + 值」交给实体自己的 handler。更新失败只记日志，审批继续走。

调用 Webhook：说明、地址、请求方式（GET / POST）、请求头 JSON、请求体 JSON，带测试连接。占位符是 `${字段}`，`id` 会换成单据 ID。它在独立线程里发，没有重试，失败调用方看不到。没有模块字段配置时，这个线程里会空指针，审批本身不受影响。

顺序是固定的：

```
节点通过：先发 Webhook，再改字段 → 流转到下一节点 → 发本节点抄送 → 作废本轮其他人的待办
整单驳回：先回滚快照（只有编辑时机）→ 再执行驳回后操作
```

回滚成功后快照会删掉。顺序写反的话，回滚会把驳回后刚写进去的字段盖掉。

## 过程中能改什么

每个节点单独配表单权限：隐藏、查看、编辑。加签出来的待办，下发给页面时被改成全部查看，这条写死了。后端只把权限附在实例详情上，保存业务数据时不校验。

加签两种：在我之前，先经过加签人再回到我；在我之后，我通过后再到加签人。或签节点上「在我之后」，加签当时就算我这一步通过，会跑通过后操作并往下走。

抄送人挂在审批节点上，来源和审批人一样，本节点通过后发出。

审批人被禁用或删除时，他名下还在审批中的待办转给直属上级；没有上级就转给 admin。转移失败只记日志。

## 卡住了怎么办

审批人为空时：自动通过、指定人员处理、转交给审批管理员。

审批人与提交人为同一人时：由提交人对自己审批、自动通过、转交给直属上级审批。转给上级但上级为空，这个人自动通过，记录写「直属上级为空, 自动通过」。

同一人重复出现，在更多设置的自动审批里选：仅首个节点需审批，后续自动同意；仅连续审批时自动同意；每个节点都需要审批。被跳过的会留一条「审批人重复出现, 后续节点自动通过」。

整节点直接过，只发生在：节点设成自动通过 / 自动拒绝，或者审批人为空且选了自动通过，或者只剩一个人、或签时命中了同人跳过 / 重复跳过。会签和依次审批是逐人跳过，不是整节点消失。一个节点上该发的待办如果全是自动同意，引擎马上继续往下走。

## 谁能做什么

更多设置里，后端真正拦的只有两个：允许加签、允许审批人撤回。撤回还要求你是这条待办的审批人，并且后续的人还没审。

只给页面用、接口不看的有四个：允许提交人撤销审批中的申请、允许审批人批量处理、同意必填、驳回必填。提交人撤销的接口也不查你是不是提交人。页面上，第一个节点通过后还能不能撤销，看的就是那个勾；配置前已发起的申请不生效，这句是页面提示，不是后端按实例记住的开关。

运行时动作：通过、驳回、加签、退回至、撤回审批、撤销审批、批量处理。

退回是打回前面某个节点重走，实例仍是审批中，不能退回到自动通过 / 自动拒绝节点。撤回是审批人撤掉自己刚做的审批。驳回是整单结束，状态变已驳回。撤销是提交人把申请撤掉，状态变已撤销，编辑时机同样回滚快照。

通过会先锁实例，并核对还在当前节点、当前轮次。批量同意按实例 ID、任务 ID 排序后再一把把锁。驳回没有这把锁，也不对轮次；批量驳回只是按查出来的顺序循环调驳回。驳回所在的类有事务，但两个人同时驳回同一条时，可能都读到同一份快照。

## 单据在不同状态下还能被怎么操作

审批状态权限是一张表：行是待提审、审批中、已撤销、已驳回、已通过，列是查看、编辑、删除、导出、转移这些业务操作。导出、转移这类批量入口会按这张表过滤。

表是空的，或者单据还没有审批状态，操作不受这张表限制。状态是「无」的，一律允许。

## 配了没用

界面上的名额上限只在前端拦：单节点审批人 15 个，抄送人 100 个成员或 15 个角色，兜底审批人 1 个。

调用 Webhook、列表上的批量编辑和批量转移负责人，都要读模块字段清单。没有这份清单，Webhook 在异步线程里失败，那两个入口到不了审批。

表单权限同理：页面不按详情里的权限渲染，等于没配。

删一条流程是软删除，同时把还在审批中的实例清掉：业务状态改回「无」，实例、待办、加签、退回记录一并物理删除，不回滚快照。自定义表单被删时，挂在它上面的流程配置是物理删除，在途实例同样只清不回滚。这两条是代码路径，没有跑过。

## 你的实体能用到哪一步

字段写死在代码里、不走动态表单时，流转本身还能用：提审、通过、驳回、加签、退回、撤回、撤销、批量、状态回写、快照回滚、待我审批、我处理的、我发起的、抄送我的、@我的、通知、评论。条件在运行时也按详情接口的属性名取值。

缺的是设计器和另外三个入口：

| 缺什么 | 原因 |
| --- | --- |
| 设计器里配条件 | 条件下拉读字段清单，没有就空 |
| 调用 Webhook | 拼参数读同一份清单 |
| 批量编辑 / 批量转移触发 | 两个入口直接读清单 |
| 表单权限的实际效果 | 后端不校验，页面自己渲染 |
